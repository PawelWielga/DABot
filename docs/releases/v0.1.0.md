# DABot v0.1.0 release notes

DABot v0.1.0 is the first public release of the self-hosted .NET browser automation engine built on Microsoft Playwright.

The release establishes a usable declarative automation runner and the first durable workflow foundation. It is intentionally a foundation release: advanced web management, multi-worker coordination, scheduling, MCP integration, and AI-authored reusable tools remain roadmap work.

## Included

### Declarative browser scenarios

- JSON scenario loading, validation, schema versioning, and stable step IDs.
- Browser actions for opening URLs, clicking, filling, pasting, reading text, waiting, delays, and screenshots.
- Locator strategies for selectors, text, and test IDs while preserving legacy selector compatibility.
- Variable interpolation and structured durable variables.
- Conditions and loops.
- Step retries with configurable delay.
- Scenario-level timeout and cooperative cancellation.
- HTTP GET/POST/PUT actions with response mapping and secret-backed bearer tokens.

### Browser sessions

- Explicit browser-session ownership.
- Ephemeral Playwright sessions.
- Persistent named browser profiles.
- Cross-process profile locking.
- Headed profile setup and headless profile health testing.

### Diagnostics

- Structured execution logging.
- JSON Lines file logging.
- Stable run correlation IDs.
- Failure screenshots and HTML snapshots.
- Machine-readable run/error reports.
- Configurable secret-value redaction.

### Durable execution

- Immutable scenario versions bound to durable runs.
- SQLite-backed run state.
- Persisted execution cursors and step attempts.
- Crash-recovery semantics.
- Durable `Suspend` / `Resume`.
- Manual resume and cancellation for supported run states.
- Single-worker retry scheduling.
- Event inbox, correlation, idempotent event delivery, durable resume work items, retry, and dead-letter handling.
- Generic durable page observers with persisted polling state and event emission.

### Interfaces

- CLI runner for one-shot and durable operations.
- Initial read-only Blazor management dashboard for run status and recent activity.
- Machine-readable JSON Schemas for scenario, configuration, and page-observer definitions.
- Runnable examples and Linux-first publish/smoke-test documentation.

## Supported scenario actions

The v0.1.0 execution layer supports:

- `OpenUrl`
- `Click`
- `FillText`
- `PasteText`
- `WaitFor`
- `Delay`
- `ReadText`
- `Screenshot`
- `CallApi`
- `If`
- `Loop`
- durable `Suspend`

See the scenario schema and examples for the exact contract.

## Known limitations

- Retry processing is intentionally single-worker. Running multiple retry workers against one durable store is not supported until leases and compare-and-swap claiming are implemented.
- Active running durable executions cannot yet be safely cancelled from another process.
- Durable workflow recovery restores persisted workflow state, not a previously live browser DOM/page. Scenarios must explicitly rebuild browser state when required.
- The Blazor web UI is an early management foundation. Scenario editing, full run details/actions, profiles, observers, events, and configuration management are not complete.
- No production authentication provider is configured for the web panel yet.
- External event transport adapters are not included; events can currently be published through the local runner/Application path.
- Multi-worker coordination, scheduling, retention/backup tooling, Docker/service deployment, health/metrics, and audit-log features remain planned.
- MCP server/client integration and the declarative dynamic Tool registry remain planned.
- The project targets .NET 8 for this release.
